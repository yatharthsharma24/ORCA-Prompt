Technical report: ORCA-Prompt

TeamName · ORCA-Prompt: A Multi-Agent ReAct Assistant for Marine Ecosystem Reasoning

Architecture

A question passes through four steps. The planner (P1) writes a JSON plan of 1-4 steps. Each step goes to a specialist ReAct agent (P2: oceanography, fisheries, biodiversity or context) that calls data tools; every data-bearing tool result is stored in an evidence ledger as E1, E2, ... with its query and source citation. The synthesizer (P3) writes a Markdown answer citing those ids. A deterministic verifier matches every number in the answer against the cited evidence, and a critic (P5) checks claim support; if either finds problems, one revision (P4) rewrites the answer. Front ends: a Streamlit app and a FastAPI web UI.

Tools and models

All six prompts run on qwen3:8b through a local Ollama server (temperature 0.1, 8k context, thinking off), chosen because it fits an 8 GB laptop GPU and follows the ReAct text format and JSON schemas. Smaller models were tested for a CPU host: qwen3:1.7b took 549 s for one question on 2 CPU threads and answered wrongly. Eleven tools cover a read-only SQLite marine database (structured query, SQL, trend with Mann-Kendall test, lagged correlation, anomaly and monthly heatwave detection, traced calculator, species lookup), BM25 search over cited notes (NOAA Coral Reef Watch, IPCC SROCC, Hobday et al. 2016) and live OBIS occurrence records.

Prompt design

ReAct prompts use plain-text Thought / Action / Action Input turns with a stop sequence before "Observation", so any local model can follow them and the trace stays readable. Each prompt states strict rules: copy numbers from observations, cite evidence ids, use the calculator for derived numbers, say when data cannot answer. Three versions of each main prompt were driven by failures in real runs (see the iteration log).

Test results

11/15 test inputs passed after hand review (7 normal, 5 edge, 3 invalid). The system refused an injected false number (T11), handled a vague question (T10), an out-of-region question (T08) and an off-topic question (T15), and rejected invalid input (T13, T14). It failed four: T09 (Hinglish; planner mapped "oil sardine" to mackerel), T01 (picked the wrong region in this run), T04 (lead paragraph merged months into wrong ranges) and T12 (invented a 2030 estimate). In T01 and T09 the number check passed numbers that were real evidence for the wrong entity. 48 offline unit tests cover tools, verifier, agents and API.

Limitations

  • Four of the five local tables are synthetic demo data (clearly labelled); real CMFRI/INCOIS/OBIS data must be loaded before use in decisions.
  • The number verifier cannot tell when a correct number is attached to the wrong entity; the critic catches some of these, not all.
  • Streamlit Community Cloud has no GPU, so live answers need the team's Ollama server to be reachable.
